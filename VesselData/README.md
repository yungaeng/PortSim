# 선박 자료 불러오기와 배치 적용

HUD에서 선박별 직접 설정 또는 불러오기 모드를 선택합니다. 직접 설정에서는 슬라이더로 수량을 정하고, 불러오기에서는 슬라이더 대신 양하/선적 목록 및 선내 적재도 CSV 선택 버튼을 표시합니다. 변경값은 대기 설정이며, 리셋 버튼을 눌렀을 때 실제 컨테이너 수·ID·위치에 적용하고 전체 시뮬레이션 진행 상태를 초기화합니다. 파일을 고르거나 모드를 바꾸는 것만으로 현재 배치는 바뀌지 않습니다.

- 선내 적재도(Stowage)는 선박의 초기 ID·수량·위치를 결정합니다. 작업 목록(Operations)은 별도로 보관하며 초기 선박 배치를 대체하지 않습니다. 불러오기 모드에는 선내 적재도가 필요합니다.
- 리셋 시 선내 적재도의 모든 컨테이너를 선박에 생성하고, 작업 목록의 LOAD 컨테이너는 야드의 크기·취급 구역에 맞는 빈 바닥 슬롯에 생성합니다. LOAD의 Bay/Row/Tier는 선박 목적지이며 야드 위치는 자동 선택합니다.
- 작업 목록을 불러오지 않았다면 선내 화물 전체를 양하만 합니다. 작업 목록을 불러왔다면 DISCHARGE에 지정한 ID만 선박 → STS → AGV → RMG → 야드로 양하하고, 목록에 없는 선내 화물은 그대로 남습니다. LOAD는 사용 가능한 크레인·차량을 확보하면 RMG → AGV → STS → 지정 선박 슬롯으로 양하와 병행하여 적하합니다. 같은 선박 Bay/Row 열의 양하와 아래층 적하가 완료되어야 해당 위치에 적하합니다.
- 양하 ID·위치는 적재도와 일치해야 합니다. 양하 대상 위에 잔류 화물이 있거나, 적하 목적지가 잔류 화물과 겹치거나, 적하 완료 배치에 하단 지지가 없으면 리셋 전에 오류를 표시합니다.
- Operations/example_operations.csv와 Stowage/example_stowage.csv를 함께 불러오면 선박 4개, 야드 적하 대기 2개로 시작하고, 양하 4건과 적하 2건을 자원·슬롯 조건에 따라 병행합니다.
- Stowage/example_stowage.csv: 4개 배치.
- 직접 설정으로 돌아오면 이전 직접 설정 수량을 복원하고 다시 슬라이더로 조절할 수 있습니다. 선택한 모드와 직접 설정 수량은 저장됩니다. 불러오기 모드에서 파일을 선택하지 않았다면 리셋 시 안내를 표시하고 현재 배치를 유지합니다.
- 헤더만 있는 선내 적재도는 빈 선박을 뜻합니다. 헤더만 있는 작업 목록은 작업 없음이며, 선내 화물은 유지됩니다.

## CSV 형식

UTF-8, 쉼표 구분, 따옴표 없는 단순 CSV입니다. 헤더와 열 순서는 예시와 동일해야 합니다.

- 작업 목록: container_id,operation,bay,row,tier
- 선내 적재도: container_id,bay,row,tier
- operation: DISCHARGE 또는 LOAD.
- 최대 2MB. 확장 선박 모델은 길이 332m, 22 Bay × 17 Row × 최대 12 Tier이며 선박당 입력 상한은 3,000개입니다. 자동 적재는 질량·GM·경사·지지·고박 및 STS 도달 범위를 검사합니다. 여러 선박의 총 물량에는 별도로 기존 야드 수용량 제한이 적용됩니다.
- 시뮬레이터 슬롯: Bay 1~22, Row 1~17, Tier 1~12.
- 예시의 갑판 표기: 홀수 Bay 1,3,...,43을 시뮬레이터 Bay 1~22에 대응시키고 Tier 82/84/.../98을 Tier 1~9에 대응시킵니다. Row는 1~17입니다. 10~12 Tier는 시뮬레이터 슬롯 표기를 사용합니다. 두 표기를 한 파일에 혼용할 수 없습니다.
- CSV의 슬롯은 40ft 컨테이너 기준입니다. Bay 간격 14m, Row 간격 2.5m로 실제 갑판 위에 배치하며 빈 Bay/Row 간격을 유지합니다. 직접 설정 모드의 자동 적재 계획으로 재배치하지 않습니다.
- 위치 중복, 범위 초과, 중복 ID, 선박 초기 배치의 상단 컨테이너 아래 지지 화물 누락은 거부하고 기존 배치를 유지합니다. LOAD 행은 선박 초기 배치의 지지 화물로 취급하지 않습니다.

## 저장과 복원

자료 루트는 Unreal 프로젝트 폴더의 상위에 있는 VesselData입니다.

선박 수, 직접 설정 수량, 선택 모드, 선택한 파일 종류와 CSV 내용은 PortSim/Saved/SimulationSettings.json에 함께 저장합니다. 실행하면 마지막으로 저장한 설정과 파일 배치로 시작합니다. 원본 CSV를 이동하거나 삭제해도 저장된 배치를 복원할 수 있습니다. 별도의 Imported 폴더는 만들지 않습니다.

실행 중 직접 설정/불러오기 모드나 수량·파일을 변경하면 다음 적용할 설정으로 저장합니다. 현재 배치는 유지되며 리셋을 눌렀을 때 변경된 설정을 적용합니다. 파일 수정 내용을 반영하려면 다시 불러온 뒤 리셋하세요.

예시의 SIMU 번호는 설명용 가상 ID이며, EDI 파일은 지원하지 않습니다.

## 300개 적재 · 100개 양하 · 100개 선적 예시

- 선내 적재도: Stowage/stowage_300.csv (300개, 3단)
- 양하/선적 목록: Operations/operations_300_d100_l100.csv (DISCHARGE 100개, LOAD 100개)
- 아래 2단 200개는 잔류하고, 상단 Tier 86의 100개를 신규 ID 100개로 교체합니다. 작업 완료 후 선내 재고는 300개입니다.
- 선박 한 척의 불러오기 모드에서 두 파일을 함께 선택하고 리셋합니다. 초기에는 선내 300개와 야드 선적 대기 100개가 생성됩니다.
- 기본 직접 설정 수량은 기존과 같이 척당 200개입니다. CSV의 3단 지원에는 변경된 코드의 빌드가 필요합니다.

## 3,000개 동시 적재 예시

- Stowage/stowage_3000.csv: 고유 ID 3,000개와 하단 지지가 있는 1~9 Tier의 실제 슬롯 배치입니다.
- 선박 한 척의 불러오기 모드에서 선택한 뒤 리셋하면 적용됩니다. 기존 300개 교환 예시도 계속 사용할 수 있습니다.
- 직접 설정에서도 선박당 최대 3,000개를 지정할 수 있습니다. 기본 시작 수량은 기존 척당 200개이며, 변경한 값은 리셋 시 적용됩니다.
- 세 선박을 각각 3,000개로 모두 채우는 9,000개 운용은 현재 야드 수용량을 초과하므로 허용하지 않습니다.

확장 선박은 기존 1,050m 안벽 안에서 중심 Y=-350/0/350m에 배치합니다. 북측 STS 운송로를 연장하고, 충전 대기 구역은 Y=520~619m의 4열 × 15대로 옮겨 인수점과 주차 차량의 간섭을 피합니다. 선박 안정성·고박 입력은 확장 개념 모델의 명시적 시뮬레이션 가정이며 실선 승인값이 아닙니다.

검증: `PortSim/Scripts/TestVesselCapacity.ps1`은 실제 게임 초기화에서 선내 3,000개 생성, 지원되는 적재 계획, 3,000개 야드 목적지 계획과 재고 수를 검사하고 종료합니다. 출고 순번별 우선 야드가 가득 차면 다른 호환 건화물 구역을 사용하며, 규격·냉동·위험물 구역·하단 지지·인출 순서·하중 조건은 유지합니다.
