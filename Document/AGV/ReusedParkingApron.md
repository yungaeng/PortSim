# 옛 AGV 대기 공간의 운반 차선 전환

후속 [입항 배치 변경](../Operations/ShipArrivalStowage.md)으로 선박 초기 좌표와 야드 계획이 달라졌다. 아래 수치는 변경 전 초기 격자 시나리오의 기록이며, 현재 코드와 직접 성능 비교하지 않는다. 현재 코드에서 경로를 비교하려면 `CompareAGVApron.ps1`을 기준 기록 재사용 없이 실행해 두 조건을 다시 측정해야 한다.

새 대기·충전소로 주차 차량을 옮긴 것만으로는 비워진 공간이 도로 그래프에 포함되지 않았다. 기존 적재 차량은 공통 안벽 차선에서 선박별 교차로까지 이동했고, 중앙에는 주차 차량을 피하던 우회가 남아 있었다.

## 적용한 경로

- 옛 대기 공간에 적재 차량용 북향·남향 전용 차선을 추가했다. 계획 좌표 X=90m/110m를 `SiteCmX`로 보정하며, 실측 도로 좌표라는 의미는 아니다.
- STS 인계 위치에서 짧게 종방향으로 출발한 뒤 해당 차선에 합류한다. 연속 회전 사이에 최소 회전 반경의 두 접선과 여유가 들어가도록 진출 위치를 선택한다.
- 가까운 RMG는 전용 차선에서 해당 야드의 기존 인수 도로로 직접 연결한다. 야드 적재 구역을 가로지르는 직선 지름길을 만들지 않는다.
- 먼 RMG는 선박 그룹별 남·중·북 횡단 도로를 통해 내륙 서비스 도로에 진입한다. 중앙 도로는 옛 주차 열을 피하던 굴곡 없이 연결한다.
- 공차의 대기열 진입 위치는 옛 33m 주차 격자 대신 실제 회전 여유로 정한다. 공차의 안벽 진입·야드 복귀·충전소 도로는 적재 전용 차선과 분리한다. 서로 가로지르는 합류 지점에는 기존 FMS 예약과 LiDAR 제어를 적용한다.
- 옛 주차 격자를 기준으로 한 중간 정지 제한을 제거하고 실제 적재 진출 지점 및 교차로 여유를 적용한다. 새 적재 차선에서도 기존 안전 후진 교착 복구가 작동한다.
- 중앙 횡단 도로 옆에 연속 회전이 겹치지 않도록 적재 진출 지점의 간격을 보정한다. 빈 STS 접근 차량도 비어 있는 옛 주차장 도로 안에서 종방향 후진으로 양보할 수 있다. 가로 도로 후진에서는 도킹 축도 실제 가로 방향으로 유지한다.
- 연속 포장, 방향 화살표 및 안내 표시를 실제 차선 좌표에 맞춰 추가했다.

장비 속도·하중·센서·도킹 정밀도·가감속·조향·차체 충돌 조건은 변경하지 않았다. 중앙 배차의 실행 준비 조건과 야드 배치 계획도 유지했다. 도로 분리는 모든 교차를 없앤다는 의미가 아니며, 합류부에는 차량 간 통행 조정이 필요하다.

도로만 바꾼 완료 실행에서는 교통 대기 평균이 줄어도 총 완료 시간이 늘었다. 인접 RMG의 30m 회전 공간 예약은 유지해야 하므로, 단순히 같은 나이의 작은 계획 순번을 먼저 배차하면 긴 적재 연쇄가 마지막에 남을 수 있었다. 이를 보완해 야드 받침→상부 적재 그래프의 **작업을 통과하는 최장 경로 길이**와 후속 화물 수를 배차 우선순위에 반영했다. 마지막 상부 화물도 자기 연쇄의 우선순위를 이어받는다.

- 평가 범위는 현재 운송 한도 안의 계획만 포함한다. 120개 검증에 한도 밖 480개의 후속 화물이 우선순위를 부풀리지 않는다.
- 실행 가능 조건(선박 접근성, 받침, 크기, RMG 및 회전 공간 준비)을 만족한 작업 중에서만 선택한다. 예약·안전 간격을 줄이지 않는다.
- 우선순위 점수는 `min(경로 길이, 8) × 120초 - 최초 접근 가능 시각`이다. 같은 점수에서는 후속 화물 수와 기존 대기 순서를 사용한다. 120초는 배차 휴리스틱이며 장비 실측 사양이 아니다. 새로 도착한 작업에 대한 우선권은 최대 960초의 나이 차이로 제한된다. 절대 최대 대기 시간을 보장하는 식은 아니다.
- AGV 선택은 기존 주행 ETA와 완료 작업량의 완만한 공정성 가중치를 유지한다. 과거 경로 비교 모드에는 이 우선순위를 적용하지 않는다.
- 텔레메트리의 `dispatch_policy`, 화물별 `dispatch_critical_path_edges`/`dispatch_unlocked_containers`, 결과 프로필의 `agv_dispatch_priority`로 적용 상태를 확인한다.

## 비교 방법

정상 실행은 새 차선을 사용한다. `-PortSimPreviousApron`은 같은 새 주차장에 기존 경로를 사용하는 비교 모드이고, `-PortSimLegacyParking`은 이전 분산 주차 모드이므로 새 차선을 활성화하지 않는다. 텔레메트리/결과 프로필의 `agv_apron_layout`과 로그 `AGV_APRON_ROUTE`로 실제 적용 여부를 확인할 수 있다.

```powershell
# 같은 코드에서 기존/전환 경로 각각 120개 실행
./PortSim/Scripts/CompareAGVApron.ps1

# -BaselineSummary는 현재 입항 배치 코드로 만든 Previous.json에만 사용할 수 있다.
# 아래 과거 검증의 ParkingComparison_20261015_224154/Depot.json은 재사용하지 않는다.
```

비교 스크립트는 환경 난수·고정 시간 간격·주차 방식 및 120개 화물 ID/사양/야드 계획의 일치를 검사한다. 기존 기록을 재사용했는지 결과 JSON에 경로를 남긴다. 일반 실행 검증의 기본 4배속과 별개로 시간 비교에는 동일한 고정 0.2초 간격을 사용한다.

## 검증 결과

첫 실행은 52개 적재 후 V122/V137의 상호 도로 예약 대기를 발견해 중단했다. 적재 진출 회전이 새 중앙 복귀 도로와 너무 가까웠고, 기존 후진 복구는 세로 서비스 도로의 차량만 처리했다. 이 실행을 완료 결과에 포함하지 않는다. 실제 두 차량의 위치·방향을 `PortSim.Traffic.ApronCrossingRecovery`에 재현하여 회전 간격과 가로 도로의 정상 조향 후진을 검증한다. 중단 당시 상태는 `PortSim/Saved/Tests/ApronComparison_20261016_025959/InterruptedCycleState.json`에 보존했다.

`PortSim.Traffic.ApronManifestRoutes`는 컨테이너 원본 Y에 인계 위치를 맞추는 호환 옵션에서 선박 3척의 출발 베이 30곳을 사용해 가까운/먼 RMG로 가는 60개 경로를 생성한다. 특히 선박 인계 Y가 중앙 도로 Y와 정확히 같아도 첫 이동이 종방향이며 회전 접선을 제공하는지 검사한다. 적재 차량의 중앙 도로 연결은 새 전용 차선부터 시작하므로, 인계 위치에서 곧바로 옆으로 가는 그래프 지름길이 생기지 않는다. 정상 실행과 120개 비교는 기존처럼 STS별 고정 인계 구역을 사용한다.

### 최종 완료 실행 (2026-10-16)

빌드와 `PortSim` 자동 테스트 **25개가 통과**했다. 통합 실행은 선박 화물 600개 중 **120개(20%)**를 실제 STS→AGV→RMG 운송·적재하고, 차량 복귀와 일시정지/비상정지/초기화를 검증해 통과했다. STS 9대 모두 운송했고 AGV는 60대 중 54대를 사용했다. 이 실행에서 실패 로그와 물리 후진 복구 완료 이벤트는 모두 0건이다. 별도의 자동 테스트에서는 기록된 교착 위치의 후진 복구를 재현했다.

동일한 난수 시드 166290927, 고정 간격 0.2초, 동일한 120개 화물·규격·야드 목적지로 비교했다. 비교 기준은 이전에 완료한 새 주차장·기존 경로 기록을 재사용했으며, 이번 실행의 새 차선·교착 복구·받침 연쇄 배차를 함께 비교한다. 각 변경의 독립적인 성능 효과를 의미하지 않는다.

| 지표 | 새 주차장·기존 경로 | 최종 변경 | 차이 |
|---|---:|---:|---:|
| 120개 최종 적재 | 9621.950143초 (160.37분) | 9617.300143초 (160.29분) | 4.65초 감소, 0.0483% |
| 차량 복귀 포함 | 9727.0초 | 9734.0초 | 7초 증가, 0.0720% |
| 화물당 교통 대기 평균 | 172.95초 | 141.37초 | 18.26% 감소 |
| STS가 든 채 AGV를 기다린 시간 평균 | 31.90초 | 38.90초 | 21.94% 증가 |

**교통 대기는 줄었지만 전체 완료 시간은 사실상 동일하다.** 복귀까지 포함하면 소폭 느리므로 전체 처리 성능이 개선됐다고 주장하지 않는다. 이전 분산 주차 기록의 최종 적재 9258.050138초와 비교하면 여전히 3.88% 느리다. 단일 시드·120개 실행의 결과이며 전체 600개나 다른 환경에서 같은 성능을 보장하지 않는다.

마지막 구간은 도로 정체보다 RMG 인수 공간 예약에 묶였다. RMG45의 C2139가 8081.40초에 완료된 후 C2511이 8095.20초에 시작해 8828.90초에 끝났고, C2331은 8842.70초에 시작해 9617.30초에 끝났다. 이 세 운송의 기록상 교통 대기는 모두 0초였다. 받침 연쇄 우선순위는 이전 마지막 화물 C2582를 앞당겼지만, 다른 화물 C2331이 마지막으로 밀려 전체 종료 시점의 이득을 상쇄했다. 따라서 새 차선 사용과 총 작업 시간 단축을 구분해야 한다. 남은 개선 대상은 안전 간격을 줄이는 것이 아니라, RMG 인수 공간의 예약과 STS 준비·배차를 연계하는 방식이다.

크기별 적재 구역 분리, 완성된 20ft 두 칸 층 15개, 20ft 두 개 동시 운송 2회, 받침이 있는 상층 적재 58개도 검사했다.
