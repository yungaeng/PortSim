# 향후 구현 계획

기준일: 2026-10-29. 사용자 요청 여섯 가지를 정리한 개발 요구사항이다. 체크된 항목은 구현·검증된 범위이며, 미체크 항목은 남은 작업이다. 이번 문서 갱신에서는 실행 코드를 수정하지 않는다. 기존 구현과의 경계는 [현재 구현 현황](ImplementationStatus.md)을 참고한다.

## 1. 선적 최적화 — 장비 대기와 배치

목표: 기존 선적 운송에 하역 알고리즘처럼 장비 대기·선배치와 다음 작업 준비를 적용한다.

- [ ] RMG 인출 준비, AGV 도착 예상 시간, STS 가용 시간, 선박 적재 순서를 함께 평가한다.
- [ ] AGV 대기 위치와 다음 차량 선배치, RMG 사전 준비, STS 인계 예약을 설계한다.
- [ ] 하역과 선적이 동시에 진행될 때 도로·크레인·인계점 예약 충돌과 기아 상태를 방지한다.
- [ ] 화물 크기·중량·취급 구역·하부 지지·목적항 순서를 유지하고, 고장·작업 취소 시 예약을 일관되게 반환한다.
- [ ] AGV 빈차 거리, 장비별 대기 시간, 선적 처리량, 전체 완료 시간을 기록한다.

완료 기준: 동일 화물·환경·시드의 기존 선적 방식과 비교하여 대기 및 완료 시간 변화를 보고한다. 순서 위반·화물 중복·예약 교착 없이 선적 완료와 AGV 복귀를 검증한다. 성능 개선 수치는 실제 측정 후 기재한다.

관련 코드: `ExportOperations.cpp`, `AGVDispatchPolicy.h`, `PortSiteLogistics.cpp`.

## 2. 배속과 무관하게 1배속 기준 물리 적용

목표: 배속은 실제 시간당 처리하는 시뮬레이션 단계 수만 바꾸고, 각 단계의 물리 규칙과 계산 간격은 1배속 기준으로 유지한다.

- [ ] AGV 구동·타이어·제동, STS/RMG 현수체·잠금, 자유 컨테이너 Chaos 물리, 환경·센서·고장 타이머의 시간 경로를 점검한다.
- [x] 월드 시간 간격을 모든 배속에서 1/60초로 고정하고 배속은 tick 대기 시간에 적용한다. 배속 전환·프레임 지연 회귀 테스트를 통과했다.
- [ ] 센서 갱신·접촉·화물 인계 순서를 물리 단계와 맞추고 화면 보간 및 관제 수집 주기를 분리한다.
- [x] 처리 성능이 부족하면 시간 간격을 늘리지 않고 실제 달성 배속을 낮추며, 진행한 시뮬레이션 시간 대비 실제 시간으로 배속을 표시한다. 지연 시간을 누적해 몰아서 처리하지 않는다.
- [ ] 실행 중 배속 변경, 일시정지·재개, 비상정지·초기화 시 시간 누적과 물리 상태를 검증한다.

완료 기준: 같은 초기 상태·난수 시드·시뮬레이션 시각의 입력으로 1/2/4/8/16배속과 낮은 FPS를 비교한다. 동일 시뮬레이션 시점의 위치·속도·제동거리·슬립·흔들림·접촉 하중·화물 소유권·작업 순서를 확인한다. 수치 허용 오차는 시험 전에 명시하고, 벽시계 완료 시간과 물리 결과 차이를 구분한다.

관련 코드: `PortSimTimeStep.cpp`, `SimulationControls.cpp`, `AGVDynamics.cpp`, `STSDynamics.cpp`.

2026-10-29: UE 5.6 빌드와 `PortSim.Playback.FixedWorldStep` 테스트 1개 통과. 실제 화면의 와이어 궤적 비교와 전체 터미널 물리 동등성·처리량 검증은 남아 있다. [상세 기록](../Simulation/PlaybackClock.md).

- [ ] 남은 대시보드 수집·엔진 tick 비용을 줄이고 설정 배속과 실제 달성 배속 차이를 재측정한다.
- [ ] 렌더링 실행·Editor PIE·대규모 실제 하역 조건에서 처리량과 물리 동등성을 함께 검증한다.
- [ ] D3D12 최초 실행의 PSO 생성 지연을 개선하고 워밍업 이후 렌더링 처리량을 측정한다. 이번 초기 20초 렌더링 측정은 0.032배로, 정상 상태 성능을 확인하지 못했다.

## 3. 적재 AGV 고장 시 Reach Stacker로 인양·인계

목표: 화물을 소유한 AGV가 고장 나면 Reach Stacker가 현장에 이동하여 화물을 인양하고, 새 AGV에 내려놓아 기존 작업을 이어가게 한다.

예정 흐름: 고장 감지 → 고장 차량 정지·현장 확보 → Reach Stacker 및 대체 AGV 배차 → 현장 접근·정렬 → 화물 결합·시험 인양 → 기존 AGV에서 분리 → 대체 AGV에 안착·인계 → 작업과 예약 승계 → 현장 해제.

- [ ] 복구 작업 상태, 담당 장비, 원래 운송 작업, 화물 ID, 목적지와 예약의 관계를 별도로 관리한다.
- [ ] 실제 도로와 회전·작업 반경을 사용하여 현장으로 이동한다. 진입 불가·공간 부족·대체 장비 부족 시 이유를 표시하고 대기한다.
- [ ] AGV·STS·RMG처럼 카메라와 LiDAR 센서를 부착하고, 설치 위치·시야·거리·주기·가림·관측 지연·고장 조건을 제어에 연결한다.
- [ ] 타이어 회전·슬립·노면 마찰·구동/제동 토크·조향·적재 중량·무게중심·하중 이동을 반영한다.
- [ ] 붐 길이·각도별 인양 능력, 전도 안정성, 집게/스프레더 접촉 마찰·미끄러짐·결합·해제를 구현한다. 마찰과 기계적 잠금의 역할을 구분하고 장비 제원과 가정값을 기록한다.
- [ ] 정렬·접촉·잠금·시험 인양·하중 검증 이후에만 고장 AGV → Reach Stacker → 새 AGV로 소유권을 넘긴다. 순간 위치 변경만으로 인양을 대체하지 않는다.
- [ ] 대체 AGV의 질량·무게중심·남은 작업·목적지·예약을 갱신한다. 기존 차량의 적재 하중은 실제 분리 시 제거한다.
- [ ] 두 개의 20ft 화물, 인양 중 센서 고장, 대체 AGV 고장, 작업자 진입, 복구 취소와 초기화를 처리한다.

완료 기준: 하역 및 선적 운송 중 고장을 주입하여 현장 출동부터 원래 목적지 완료까지 검증한다. 화물 ID·수량·질량 보존, 단일 소유권, 실제 결합/분리, 충돌·과부하·전도·미끄러짐 제한, 예약 해제를 확인한다. 실패 시 화물을 안전하게 유지하고 원인을 관제에 표시한다.

관련 코드: `PortSupportVehicle.h/.cpp`, `EquipmentRecovery.cpp`, `AGVDispatchRecovery.cpp`, `PortContainerActor.h`, `DashboardTelemetry.cpp`.

## 4. 품목에 맞는 하역·선적 구역 배정

목표: 기존 일반·냉동·인화성·부식성 구역 규칙을 바탕으로 품목에 적합한 배정을 하역·선적·재계획에 일관되게 적용한다.

- [ ] 대시보드·에디터 표시 구역과 실제 배정 정책의 차이를 정리하고 동일한 구역 정의를 사용한다.
- [ ] 품목, 취급 타입, 온도 요구, 위험물 그룹과 각 야드 구역의 허용 조건을 공통 정책으로 정의한다.
- [ ] 하역 목적지 선정뿐 아니라 수출 화물 초기 배치·선적 인출 순서·고장 재배정에도 같은 정책을 적용한다.
- [ ] 냉동이면서 위험물인 화물 등 복합 제약과 미분류 품목의 처리 정책을 정한다. 수용 가능한 구역이 없으면 일반 구역으로 우회 배정하지 않고 사유와 대기를 표시한다.
- [ ] 구역 적합성을 먼저 검사한 후 이동 거리·대기량을 최적화한다. 크기·지지·층별 중량·출고 순서 조건을 유지한다.
- [ ] 화물 상세와 야드 화면에 선택 구역, 배정 근거, 재배정 이력과 실패 원인을 표시한다.

완료 기준: 일반·냉동·인화성·부식성·복합 조건·미분류·구역 포화·담당 RMG 고장 사례를 양방향 운송에서 검증한다. 허용하지 않는 구역/스택 배정은 0건이어야 한다. 실제 위험물 격리 규정이나 냉동 전력·온도 물리까지 확장할지는 별도 요구사항으로 확정한다.

관련 코드: `CargoInformation.h`, `YardStackingPolicy.h`, `ExportOperations.cpp`, `EquipmentRecovery.cpp`.

## 5. 컨테이너 무게에 따른 선박 하중 이동과 흔들림

목표: 컨테이너의 무게와 적재 위치, 선적·하역에 따른 하중 분포 변화를 선박 자세와 흔들림에 반영한다. 기존 파랑·너울 기반 선박 운동에 적재 하중의 영향을 연결한다.

- [ ] 컨테이너 총중량(자중+화물), 적재 위치와 화물 무게중심을 사용해 선박 총질량·무게중심·관성 및 하중 분포를 계산한다.
- [ ] 선적·하역의 실제 지지·결합·분리 시점에 선박과 크레인 사이의 하중 전달을 반영한다. 화물 하중을 중복 계산하거나 예약 단계에서 미리 제거하지 않는다.
- [ ] 좌우·선수/선미의 비대칭 적재와 순차 하역에 따른 횡경사(heel), 종경사(trim), 흘수 변화와 과도 흔들림을 구현한다.
- [ ] 부력·복원력·감쇠와 파랑·너울 응답을 적재 상태에 연결하고, 선박 제원과 미확인 가정값을 구분해 기록한다.
- [ ] 변경된 선체 자세·속도·가속도를 선상 컨테이너, STS 픽업 목표·센서·접촉 판정에 같은 시점으로 반영한다.
- [ ] 대칭/비대칭 적재, 무거운 컨테이너의 한쪽 집중, 연속 선적·하역 및 배속 변경 사례를 검증하고 관제에 선박 하중·무게중심·자세를 표시한다.

완료 기준: 동일 총중량에서 적재 위치 차이에 따른 선체 응답과, 동일 위치에서 중량 차이에 따른 응답을 비교한다. 선적·하역 중 질량·하중 전달의 일관성, 선체와 화물의 운동 일치, 1배속/8배속의 동일 시뮬레이션 시점 결과를 확인한다. 허용 오차와 선박 모델의 적용 범위는 시험 전에 정한다.

## 6. 제어 입력에 따른 실시간 1배속·사전 계산 배속 재생 전환

2026-10-29 소스 시제품 추가: 기존 현수체 수치 모델을 복제해 기본 0.5초 미래 버퍼를 만들고, 명시적 입력 이벤트에 따른 1배속 전환·미래 폐기·재생 복귀를 구현했다. **사용자 요청으로 빌드·테스트·실행하지 않았으며 실제 터미널에는 미연결**이다. 따라서 아래 완료 체크는 유지한다. [구현 범위와 사용 흐름](../Simulation/ShortLookaheadPrototype.md).

목표: 환경 변수 제어가 없을 때는 1배속 기준 물리 규칙과 고정 시간 간격으로 미래 구간을 화면 없이 사전 계산하고, 저장된 결과를 설정 배속으로 재생한다. 환경 변경 입력을 감지하면 현재 표시 시점에서 실시간 1배속으로 전환하여 변경을 적용한다. 입력이 일정 시간 없고 미래 결과가 충분히 준비되면 사용자가 설정했던 배속으로 복귀한다.

예정 흐름: 사전 계산·배속 재생 → 제어 입력 감지 → 현재 표시 시점의 상태 복원 → 기존 미래 결과 폐기 → 1배속에서 입력 적용·실시간 계산 → 무입력 대기 조건 충족 → 변경된 조건으로 미래 구간 재계산 → 재생 버퍼 확보 후 설정 배속 복귀.

- [ ] 먼저 짧은 미래 구간으로 시제품을 만들어 상태 복원과 물리 연속성을 검증한다. 사전 계산용 월드/프로세스와 표시용 상태를 분리하고, 미래 계산이 현재 작업 상태를 변경하지 않도록 한다.
- [ ] 재생 시각과 계산 완료 시각을 따로 관리하고, 복원 가능한 체크포인트·입력 기록·재생 결과를 저장한다. 계산에서는 환경·센서·제어기·Chaos의 순서와 고정 시간 간격을 유지한다.
- [ ] 바람·파랑 등의 환경 변경뿐 아니라 고장 주입, 작업자 진입, 작업 변경 등 미래 결과에 영향을 주는 모든 입력을 감지한다. 이미 예약된 사건과 자연적인 환경 변화는 사전 계산에 포함한다.
- [ ] 입력 발생 시 계산이 앞서 도달한 시점이 아니라 현재 화면에 표시된 시점으로 복원한다. 위치·속도, 현수체 각도·각속도, 센서·제어기 상태, 작업·예약·소유권, 타이머·난수 상태와 Chaos 접촉·구속·수면 등 재개에 필요한 상태의 복원 가능성을 검증한다.
- [ ] 상태 복원이 끝난 뒤 입력을 정확히 한 번 적용하고, 기존 조건의 미래 결과와 진행 중인 계산을 무효화한다. 연속 입력이나 계산 취소와 겹쳐도 오래된 결과가 다시 사용되지 않도록 한다.
- [ ] 실시간 1배속 전환 중에도 원래 요청한 배속을 보존한다. 무입력 대기 시간, 사전 계산 구간 길이, 배속 복귀에 필요한 버퍼량은 설정 가능하게 하고 측정으로 결정한다.
- [ ] 버퍼가 소진되면 준비 대기 또는 실시간 계산으로 전환한다. 계산하지 않은 미래로 건너뛰거나 물리 시간 간격을 늘려 따라잡지 않는다. 계산 처리량이 재생 속도보다 낮으면 지속 배속이 불가능함을 상태 표시로 알린다.
- [ ] 대시보드·운반 완료·통계·외부 파일은 재생 시점까지 확정된 결과만 공개한다. 폐기된 미래의 작업 완료나 이벤트가 중복 기록되지 않도록 한다.
- [ ] 일시정지·재개, 비상정지·초기화, 배속 변경, 버퍼 경계 및 반복적인 환경 제어에서 계산 취소·복원·재생 전환을 검증한다. 화면에는 실시간/준비 중/배속 재생 모드와 실제 달성 배속을 표시한다.

완료 기준: 동일 초기 상태·시드·시뮬레이션 시각의 입력으로 연속 1배속 실행과 전환 방식을 비교한다. 와이어 흔들림·속도·접촉 하중의 전환 오차, 화물 단일 소유권, 작업·예약·이벤트의 일치를 확인한다. 허용 오차를 시험 전에 정하고, 입력 반영 지연·사전 계산 처리량·버퍼 소진·메모리 사용량도 측정한다. Chaos 상태 복원과 재개가 검증되기 전에는 전체 적용 완료로 표시하지 않는다. 사전 계산은 계산량을 없애는 방법이 아니므로 무대기 8배속을 보장하지 않는다.

## 권장 진행 순서

1. 1배속 기준 물리와 비교 기록 체계를 확립한다.
2. 짧은 구간의 사전 계산·상태 복원 시제품으로 제어 입력 시 1배속 전환과 배속 복귀 가능성을 검증한다.
3. 품목·구역 공통 정책과 양방향 배정 검증을 정리한다.
4. 선적 장비 대기·배치를 최적화하고 기존 방식과 비교한다.
5. Reach Stacker 주행·센서·인양 물리를 구현한 뒤 적재 AGV 복구 흐름을 연결한다.
6. 컨테이너 중량·적재 위치에 따른 선박 하중 이동과 흔들림을 구현하고 선적·하역에 연동한다.

각 항목 완료 시 구현 현황, 상세 설계, 시험 조건·실측 결과를 함께 갱신한다.
