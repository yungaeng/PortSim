# 터미널 체크포인트 배속 재생

기준일: 2026-10-30. 사용자가 지정한 범위에 따라 Chaos 내부 상태 복원은 제외한다.

## 동작

통합 터미널의 환경·센서·제어기·배차·예약·화물 운동을 기존 1/60초 간격으로 먼저 계산한다. 요청 배속만큼의 계산 단계를 한 화면 체크포인트로 묶고, 엔진 프레임은 60Hz를 목표로 저장한 상태를 재생한다. 실제 60fps와 요청 배속 달성은 계산·렌더링 부하에 따라 달라진다.

사전 계산은 게임 스레드 안에서 수행한다. UObject를 작업 스레드에서 변경하지 않는다. 미래 계산 후 현재 표시 체크포인트로 복원하고, 재생할 체크포인트만 확정한다. 별도 프로세스나 전체 운송 종료까지의 일괄 계산 방식은 아니다.

환경 setter, 승인된 대시보드 장비 명령, 초기화 및 연결된 에디터 속성 변경은 미래 버퍼를 즉시 폐기한다. 이미 월드에 유지된 현재 표시 상태에 입력을 적용하고, 요청 배속은 보존한 채 1배속으로 실행한다. 마지막 입력 뒤 실제 시간 2초가 지나면 새 조건으로 계산하고 버퍼가 준비되면 재생한다. 자연적인 환경 변화는 외부 입력으로 취급하지 않는다. 새 입력 경로를 추가할 때는 NotifyExternalSimulationInput 연결이 필요하다.

## 복원과 출력

체크포인트는 환경 난수·누적 상태, 제어기·센서·현수체, AGV 동역학, 화물 운동·소유권, 작업·예약·진행 시간·보고서 상태와 장면의 이동 가능한 구성 요소를 보관한다. 약한 객체 참조가 만료되어 복원이 불가능하면 작업을 중지한다. 미래 계산 중 로그와 보고서·대시보드의 공개를 보류하고, 재생 시점에 확정한 결과만 공개한다.

월드에 물리 시뮬레이션 중인 몸체가 있으면 수면 중이어도 사전 계산을 사용하지 않는다. 계산 도중 화물이 자유 물체로 전환되면 해당 미완료 묶음을 버리고 복원한다. 그 경계부터 기존 고정 단계 실시간 실행으로 전환한다. Chaos 접촉·구속·수면 이력은 캡처하거나 되감지 않는다. 이 경로에서도 사용자의 요청 배속을 유지하며, 외부 입력 대기 중에만 1배속이 적용된다. 엔진 비동기 물리·물리 예측 설정도 사전 계산 제외 조건이다.

## 상태와 설정

- live: 일반 실시간 실행 또는 1배속.
- live_input_hold: 외부 입력 후 1배속 대기.
- preparing: 재생 버퍼 준비 또는 소진 후 준비.
- replay: 준비한 체크포인트 재생.
- live_chaos: Chaos 또는 물리 설정 경계로 기존 실행 경로 사용.

대시보드는 요청·실제 달성 배속, 모드와 버퍼 시간을 표시한다. 버퍼 소진 시 계산하지 않은 시점으로 건너뛰지 않으며 물리 간격도 늘리지 않는다.

PortSim.BufferedPlayback 기본값은 1이다. 0 또는 실행 인수 -PortSimNoReplay로 기존 경로를 선택할 수 있다. PortSim.ReplayWindowSteps와 PortSim.ReplayBudgetSteps는 기본 16, 설정 범위 1~60이다. 실제 목표 버퍼는 화면 묶음 두 개 이상이고, 프레임별 계산 예산도 화면 묶음 한 개 이상이다. 요청 8배속이면 한 묶음은 8단계, 16배속이면 16단계다. 입력 대기 2초는 PlaybackInputGate의 정책이며 콘솔 설정은 아니다.

## 검증과 재현

- BuildPortSim.ps1: UE 5.6 Development Editor 재빌드 성공.
- PortSim.Playback 자동화 4개 모두 Success: 고정 시계, 관제 수집 주기, 현수체 시제품, 실제 터미널 체크포인트 검사. 로그: PortSim/Saved/Logs/TerminalReplay_Regression.log. 엔진 초기화의 기존 Condition failed 메시지와 자동화 최종 판정은 구분한다.
- 체크포인트 검사: 위치·센서·예약·화물 소유권 복원, 동일 난수 상태 재계산, 미래 상태 비노출, 8단계 기준과 8배속 재생 일치, 입력 즉시 버퍼 폐기·1배속, 일시정지, 수면 Chaos 제외.
- Dashboard에서 node --test tests/*.test.mjs: 35개 통과. PowerShell에서는 Get-ChildItem으로 테스트 경로를 열거해 node에 전달한다.

배속 측정은 PortSim/Scripts/MeasurePlayback.ps1 -PlaybackRate 8 -Seconds 20으로 실행한다. -NoReplay는 기존 경로 비교용이며, -Render는 실제 렌더링을 켠다. 실행 로그와 JSON의 실제 달성 배속을 기준으로 판정한다.

이번 null RHI 측정은 요청 8배속, 시드 166290927에서 실제 20.076초 동안 시뮬레이션 153.35초를 진행하여 **7.638배**였다. 파일은 PortSim/Saved/TerminalReplay_Final.json 및 Saved/Logs/TerminalReplay_Final.log다. 이 측정 구간의 운반 완료는 0건이다. 과거 관제 최적화 측정 7.702배와 동일 빌드의 대조 실험은 아니므로 추가 처리량 향상을 주장하지 않는다. 목적은 엔진 프레임과 모델 계산 단계를 분리하는 것이며, 전체 운반 완료·렌더링 60fps·장시간 동등성·최대 메모리 검증은 별도로 남는다.

## 코드 위치

TerminalReplay.cpp가 계산·재생 전환과 결과 확정을, TerminalCheckpoint.cpp가 상태 캡처·복원을 담당한다. QuayCrane.cpp 및 TerminalSiteOperations.cpp가 기존 실행에 연결하고, PortSimTimeStep.cpp가 시계를 제어한다. TerminalReplayTests.cpp가 실제 터미널 객체를 이용한 복원 검사를 제공한다. 현수체 작업 스레드 시제품은 별도 기능이며 [이력 문서](ShortLookaheadPrototype.md)에 보존한다.
