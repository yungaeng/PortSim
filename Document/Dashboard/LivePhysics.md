# 실시간 AGV 물리와 돌발상황

## 웹 사용

언리얼에서 터미널을 실행한 뒤 웹의 **실시간 물리 · 돌발상황** 메뉴를 연다. 기존 독립 시험 보고서 표를 현재 화면에서 사용하지 않는다.

- **제어할 장비**: STS/RMG/AGV를 고른 뒤 고장 발생·수리를 실행한다. 크레인은 카메라 재부팅·센서 현장 수리·갠트리 고장을 구분한다.
- **작업자 진입**: 제어 장비로 AGV를 고르면 진입 거리를 입력하고 작업자를 발생·제거할 수 있다. 현재 날씨와 실제 적재 상태를 사용한다. 진행 방향의 예약된 직선 도로와 안전 정지 조건은 엔진이 검증한다.
- **관측할 AGV**: 제어할 장비와 별도로 관측 차량을 선택할 수 있다. 속도·슬립·좌우 하중이동률 그래프와 타이어 마찰, 현재 속도의 계산 제동거리, 실제 제동 기록, 바퀴별 RPM/수직하중/토크, IMU, 질량·CoG·롤/피치, FMS/LiDAR 상태를 현재 엔진에서 읽는다.
- **터미널 오버뷰**: 같은 화면 아래에 실제 좌표와 경로, 현재 영향받는 장비와 이력을 표시한다. 장비 고장 및 작업자 영향은 기존 엔진의 실제 예약/대기 관계를 따른다.

날씨는 **관측 전용**이다. 사용자의 2026-10-28 요청에 따라 웹의 비·바람·눈·노면 설정 UI와 변경 API를 제외했다. 언리얼 환경 컴포넌트의 현재 강수·강설·바람·수막·적설·마찰계수만 읽으며, 날씨 설정 작업은 팀원이 진행할 수 있도록 남긴다. 기존 언리얼 날씨 설정·계산 코드는 변경하지 않았다.

웹의 과거 젖음·편심 고정 시험 명령도 거절한다. 기존 엔진 내부의 독립 물리 시험과 기록 조회는 유지하지만, 실시간 웹 제어는 현재 환경·화물을 보존하는 작업자 진입만 사용한다. 웹 연동 검증 스크립트는 `Dashboard/tests/live-worker-intrusion.mjs`다.

## 갱신

엔진의 물리 계산과 별도로 벽시계 약 1초마다 스냅샷을 받는다. 그래프는 선택 AGV의 최근 180개 관측을 시뮬레이션 초 축으로 표시한다. 배속 실행에서는 관측 사이에 여러 시뮬레이션 초가 지나갈 수 있고 짧은 순간의 변화가 그래프에서 빠질 수 있으므로, 엔진이 계산한 누적 최대 슬립·하중·제동 기록도 함께 확인한다.

실행/차량이 바뀌거나 시간이 초기화되면 그래프를 비운다. 같은 시뮬레이션 시각의 중복 샘플은 추가하지 않는다. 입력 칸을 편집하거나 이력을 펼쳐도 관측 영역의 갱신은 유지한다. 엔진 기록이 5초 이상 새로 들어오지 않으면 실시간 표시와 제어를 해제하고 마지막 기록임을 표시한다. 과거 벤치 보고서를 실시간 값으로 바꿔 부르지 않는다.

일반 FMS/차량 LiDAR 정지는 기존의 강제 정지 제약이다. 작업자 돌발 진입의 급제동은 타이어 접지력으로 정지까지 적분한다. 화면에 두 방식을 구분하며, 강제 정지에서 유효한 물리 제동거리 기록을 만들지 않는다.

## 처리량 개선

현재 운용 구조에서 별도 STS 대기 베이를 사용하는 빈 AGV 선배치를 추가했다. STS당 최대 한 대이며, 현재 작업과 다음 차량의 접근을 겹친다. 기존 주차장 도로가 비워진 고정 인계 구성에만 적용한다. 기존 점유 주차장 또는 원본 컨테이너 Y에 인계점을 맞추는 옵션에서는 추가 선배치를 하지 않는다. 고장 STS의 사용하지 않는 대기 차량은 검증된 대기 베이에 도착한 뒤 기존 도로로 복귀한다.

RMG가 앞선 화물을 집어 본 권상을 시작했거나 이미 출차 중이면 다음 작업 하나의 STS 집기를 예약할 수 있다. 이 예약은 RMG 진입로 점유권이 아니다. 실제 진입로가 해제될 때까지 다음 AGV는 STS 인계 위치에서 대기하고, 하나의 RMG에 두 개의 다음 작업을 예약할 수 없다. 아래 컨테이너가 실제로 놓이지 않았으면 예약을 허용하지 않는다. 고장 재계획 시에는 새 목적지의 실제 예약 상태를 적용한다.

먼 야드 경로는 세 실제 횡단도로를 방향이 있는 도로망과 현재 점유 비용으로 비교한다. 초기 야드가 비어 있으므로 불필요한 아래층 예약 의존성에 예상 STS 한 사이클의 계획 비용을 주어, 합법적인 빈 바닥 자리를 활용한다. 이 비용은 실제 크레인 동작 시간을 강제로 줄이는 값이 아니다. 크기 분리·위험물/냉동·출고 순서·하중·20ft 두 받침 조건은 여전히 적재 가능 여부를 결정한다.

STS 화면에는 누적 평균과 별도로 **최근 실제 60분 인계 수**를 추가했다. 실행이 1시간에 도달하기 전에는 이 값을 시간당 목표 달성 근거로 표시하지 않는다. 목표는 사용자 요구인 STS당 25개 이상이며, 실제 검사 결과와 구분한다.

주차장 출구의 다른 차량 예약과 겹치는 빈 차량은 새 배차에서 제외한다. 이미 배차된 차량이 45초 이상 FMS에서 막혔더라도 **자기 주차 칸 안에 정지한 빈 차량**만 교체할 수 있다. STS 인계·화물·야드 예약을 교체 차량으로 함께 넘기고 기존 차량에는 60초의 재선택 유예를 준다. 도로에 진입한 차량, 움직이는 차량, 적재 차량과 돌발상황 차량에는 이 취소 방식을 적용하지 않는다. 교체 이력은 웹에 남는다.

야드에서 돌아오는 빈 차량이 주차장 선배치 차량보다 예상 도착이 15초 넘게 빠르면, 아직 자기 주차 칸에 정지한 선배치만 취소하고 복귀 차량에 STS 대기를 배정한다. 이미 도로에 진입했거나 STS 대기 베이에 도착한 차량은 이 비교로 빼앗지 않는다. 후진 교착 복구 중인 차량 역시 취소 대상에서 제외한다. 도착 예상은 계획용 거리·속도 추정이며 실제 도로 점유·차륜 물리는 계속 적용한다.

가까운 야드는 에이프런에서 이어지는 엔진의 진입도로로 접근한다. 혼잡 우회가 153/167m 서비스 도로에서 진입 직전 약 6m만 남기는 회전을 만들지 않도록 한다. 실제 도로 예약·LiDAR·충돌 검사는 이 접근에도 적용한다. RMG 진입권이 없으면 기존 진입점에서 정차하고, 진입권이 있으면 검증된 곡선 경로로 최종 인계점까지 진행해 정밀 정차한다. 불필요한 추가 정차를 만들지 않으며, 위치를 순간 보정하거나 횡이동시키지 않는다.

## 검증 기록

웹 검사 34개와 STS/RMG 정상·고장 픽업 검사 19개를 수행했다. 네이티브 검사 47개에는 현재 환경 관측값 일치, 다음 야드 예약 상한, 실제 진입권 해제 조건, 대기 베이와 출차/입차 동선의 차체 간격, 주차장 미출발 차량의 배차 교체, 허용된 접근축에서 적재 차량의 좌우 2m 오차·전후진 정차, 혼잡 예약이 있는 STS5→야드 접근 경로 전체의 주행을 포함한다. 웹에서 날씨 명령과 과거 젖음 고정 시험 명령을 만들어 보내도 거절되는 것을 검사한다.
