# 웹 작업자 돌발 진입

웹 터미널 오버뷰나 장비 목록에서 AGV 선택 → **오류·돌발상황 → 작업자 돌발 진입**을 연다. 차량 선단부터 작업자 표면까지 거리를 5~80m로 입력한 뒤 **작업자 진입 발생**을 누른다. 현재 노면·화물 질량·CoG를 유지하며 빈 차·20/40/45ft·고정된 두 20ft 적재도 사용할 수 있다. 기존 젖음·편심 40ft 시험은 별도다.

실제 시뮬레이션이 실행 중이어야 한다. 차량이 1m/s 이상 직선 주행 중이고, 진입 거리+10m 이상의 직선 도로 예약이 있어야 적용한다. 대기·회전·도킹 중이거나 예약이 부족하면 엔진이 거절 사유를 응답한다. 실행/제어 세션과 명령 유효 시간도 확인한다. 명령 접수와 엔진 적용은 구분한다.

작업자는 입력 시점의 차로 전방에 즉시 나타나서 정지하는 기하학적 장애물이다. 실제 보행·횡단 애니메이션이나 임의 월드 좌표 배치는 포함하지 않는다. LiDAR 스캔과 반응 지연 후 기존 타이어 물리로 제동하며 경로·인계 진행을 보류한다. 스캔/반응/제동 계수는 에디터 Emergency Test의 가정값을 실행 시 복사한다. 일반 진입은 화물을 고정한 것으로 계산하고 기존 환경을 계속 사용한다. 젖음·CoG 강제 변경을 하지 않는다.

오버뷰에서 빨간 작업자 표식을 클릭하면 해당 AGV를 선택한다. 현재 작업자 영향 목록과 각 장비 상세 화면에 다음 실제 의존 관계를 표시한다.

- FMS 대기 중이며 현재 도로 차단 차량이 상황 차량 또는 그 대기열인 AGV.
- LiDAR 안전정지 중이며 앞차 ID가 위 대기열에 해당하는 AGV.
- 해당 AGV에 배정되어 실제 인계 대기 중인 STS.
- 해당 AGV가 인수·출차 예약을 유지하고 있는 비작업 RMG. 예약 유지와 실제 작업 정지를 구분한다.

관계가 해소되면 주황색 표시·현재 목록을 지운다. 발생·영향 시작·해소·작업자 제거 이벤트는 기존 recovery_events 최근 128건 이력에 남긴다. 영향 지속 시간은 시뮬레이션 시간을 사용하며 단순 근접·미래 목적지만으로 장비를 연결하지 않는다. 전체 장비가 멈추거나 계획이 반드시 재배정된다고 표시하지 않는다. 주변 장비는 실제 FMS·LiDAR·인계 제어에 따라 움직인다.

안전 정지·화물 위치 유지가 확인된 후 **작업자 제거 · 운송 재개**로 장애물을 제거한다. 실제 대기 관계가 풀리면 후속 장비도 진행한다. 접촉·화물 이동·고정장치/접촉 한계 초과는 전체 안전 정지 후 초기화가 필요하다. 완료 결과는 다음 상황/초기화 전까지 남으며 독립 물리 시험 보고서를 덮어쓰지 않는다.

## 검증 기록 (2026-10-27)

UE 5.6 빌드, 웹 32개·네이티브 42개 회귀가 통과했다. 현재 조건을 유지한 빈 AGV 물리 제동, 잘못된 거리 거절, 실행 시 설정 복사, 실제 FMS/간접 LiDAR 대기·RMG 예약 연결, 대기 해소 시 영향 제거 및 이력 보존을 확인했다. 브라우저 확인 중 완료 결과 중복 표시와 과거 차단 ID만으로 연장되는 웹 영향 표시를 보완하고 관련 웹 11개 시험을 다시 통과했다.

실제 웹→엔진 시험은 빈 AGV-103에 20m 전방 작업자를 주입했다. 부족한 직선 예약 구간에서는 명령이 거절됐고, 유효한 구간에서는 감지 0.05초·제동 시작 0.25초·정지 2.5초, 제동 이동 4.679m·최소 이격 13.623m로 안전 정지했다. 현재 날씨·화물 조건을 유지했고 AGV-112의 실제 FMS 대기를 포착했다. 작업자 제거 뒤 AGV-103과 AGV-112의 대기가 풀렸으며 현재 영향 목록이 비고 발생·해소 기록은 남았다. 이번 실시간 사례에서 STS/RMG 영향까지 관측한 것은 아니며 해당 의존 관계는 엔진 상태 조건과 네이티브 시험으로 구분해 확인했다.

증거는 `PortSim/Saved/Tests/WorkerIntrusion_WebIntegration.json`, `WorkerIntrusion_RuntimeActive.json`, `WorkerIntrusion_RuntimeReleased.json`, `WorkerIntrusion_Web.png`이며 네이티브 로그는 `Saved/Logs/WorkerIntrusion_FinalUnits.log`다. 화면의 거리 입력은 다음 상황에 적용할 값이고 결과의 **발생 시 진입 거리**는 실제 적용된 값이다.

영향 시작·해소 시각은 약 1초 간격의 웹 내보내기에서 해당 관계를 관측한 시뮬레이션 시각이다. AGV 물리의 감지·제동 시각과는 별개이며, 배속/무제한 시험에서는 관측 사이 시뮬레이션 시간 간격이 길어질 수 있다.

작업자 주입·해제를 포함한 120/600개(20%) 운송과 AGV 복귀 회귀도 통과했다. 9개 STS, 지지된 상부 적재 58건, 20ft 두 자리 적재층 13개와 규격 분리를 확인했다. 마지막 적재 9,397.55014초, 복귀 완료 9,591.5초다. 건조 기본 환경·선박 운동 OFF·기존 바람 조건이며 성능 비교 시험이나 600개 전체 완료 결과는 아니다. 요약은 `Saved/Tests/WorkerIntrusion_Normal120.json`, 로그는 `Saved/Logs/SiteTest_Normal_Depot_Reused_48468.log`다.

추가로 STS 레퍼런스를 적용한 실제 크레인 제어기의 인계 대기 상태를 시험에 구성하여, 간접 AGV 대기열 → STS 인계 대기와 RMG 예약 유지 연결을 확인했다. 이 시험의 설정 누락을 보완한 뒤 관련 시험만 재검증했다. 최종 빌드와 보강한 영향 추적 시험은 통과했으며 로그는 `Saved/Logs/WorkerIntrusion_CraneImpacts.log`다. 실제 터미널 운송 코드는 최초 전체 회귀·운송 검증 이후 변경하지 않았다.
