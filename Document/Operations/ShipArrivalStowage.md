# 입항 선박의 실제 초기 적재 배치

## 기존 상태 확인

야드는 이미 20/40/45ft 전용 칸으로 분리했고, 20ft는 두 자리를 갖는 셀을 사용했다. 반면 선박은 `TerminalSite.cpp`에서 컨테이너 순번으로 행·베이·층을 정한 뒤 규격과 중량을 부여했다. 같은 열의 위아래 크기나 목적항이 일치한다는 보장이 없었다.

`PlanShipStowage`는 목적항·중량·GM·고박을 계산했지만 `ship_loading_preview`로만 내보냈다. 계산된 Bay/Row/Tier는 실제 초기 Actor 좌표에 적용되지 않았고, 미리보기의 갑판 높이 12m도 실제 갑판 상면 4.5m와 달랐다. 기존 컨테이너 바닥 4.4m는 갑판 중심에 해당해 10cm가 잠기는 오차도 있었다. 200개 초과 예약은 같은 좌표의 숨긴 wave로 관리했다.

## 확인한 선박 적재 기준

실제 선박은 크기만으로 분류하지 않는다. 선박별 사용 가능한 셀·지지점·냉동 전원과 목적항/기항 순서, 총중량 및 무게중심, 스택·갑판·컨테이너 강도, 복원성, 고박, 위험물 취급 조건을 함께 고려한다. 안전·구조 제약을 목적항 점수나 작업 속도 점수로 무시할 수는 없다.

- [IMO CSS Code](https://www.imo.org/en/ourwork/safety/pages/css-code.aspx): 선박에 적합한 배치·고박 장치와 Cargo Securing Manual을 바탕으로 계획하고, 선박 운동에 따른 힘을 고려한다.
- [IMO VGM 안내](https://www.imo.org/en/mediacentre/pressbriefings/pages/new-ship-safety-rule-to-prevent-loss-of-containers-enters-into-force.aspx): 선박 적재 계획 전에 확인된 총중량 정보가 필요하다. 프로젝트의 합성 질량은 실제 VGM 증명서가 아니다.
- [선박 적재 최적화 원문 연구](https://arxiv.org/abs/2408.08224): 목적항별 블록 배치와 재취급 방지, 크레인 작업 시간, 트림·굽힘 모멘트 등 여러 제약을 함께 다룬다. 본 구현은 해당 논문의 최적화 모델을 구현한 것은 아니다.
- [DNV 컨테이너 고박 계산](https://www.dnv.com/maritime/insights/topics/next-generation-container-lashing/container-lashing-rules/): 실제 고박 검토는 3차원 변형·비틀림·동적 하중 등을 다룬다. 이 프로젝트의 정적 근사는 이를 대체하지 않는다.

`무거운 화물은 아래`와 `규격별 동일 열`은 본 모델이 채택한 보수적인 배치 정책이다. 실제 선박의 모든 혼합 규격 적재를 일률적으로 금지하는 규정이라는 뜻이 아니다. 허용되는 셀 조합·지지·고박은 선박별로 확인해야 한다.

## 적용 내용

1. 실제 선박 초기화에서 화물별 규격·예약 목적항·중량·무게중심으로 적재 계획을 계산한다. 계획이 실패하면 명확한 오류로 정지하며, 잘못된 격자 배치로 조용히 대체하지 않는다.
2. 선박당 10개 종방향 베이와 10개 횡방향 행을 사용한다. 18m 베이 간격, 3m 행 간격, 4.5m 갑판 상면은 현재 블록아웃 선체에 맞춘 **가상 셀 제원**이다. 실제 선박 도면의 Bay 번호 체계가 아닌 1부터 시작하는 내부 인덱스다.
3. 20ft는 한 셀의 두 독립 자리(중심 간격 6.2m)에 놓는다. 40/45ft는 긴 셀 한 자리를 사용한다. 한 셀에 다른 규격을 섞지 않으며, 위층에는 같은 자리의 실제 아래 컨테이너가 있어야 한다. 20ft 두 자리 합산 중량도 셀 한계를 넘지 못한다.
4. 기항 순서는 늦은 항구가 아래, 빠른 항구가 위가 되도록 제한하고, 호환되는 열에서는 무거운 화물을 아래에 둔다. 스택 중량과 받침 컨테이너 위 누적 하중, GM 범위·횡경사·정적 고박 근사를 검사한다. 좌우 균형과 종방향 무게중심 편차를 후보 점수에 반영한다.
5. 현재 가상 선박은 중앙 두 행의 냉동 전원, 서로 반대쪽 끝 베이의 인화성/부식성 모의 화물 구역, 끝 베이의 45ft 대응 셀을 선언한다. **실제 선박의 설치 정보나 IMDG 물질별 격리 거리로 해석하면 안 된다.** UN 번호·등급별 격리 행렬은 아직 없다.
6. 2~8단 후보를 휴리스틱으로 순서대로 시도한다. 전역 최적화가 아니므로 2단 시도의 실패가 모든 2단 배치의 불가능을 증명하지는 않는다. 200개를 넘겨도 숨긴 컨테이너를 같은 좌표에 겹쳐 두지 않는다. 선체·높이·중량 한계를 충족하지 못하는 예약은 실패한다. 예약 수가 늘어도 무조건 적재 가능하다는 보장은 없다.
7. 계산된 위치를 실제 컨테이너 Actor와 manifest 초기 좌표에 적용하고, 실제 종방향 위치로 담당 STS를 다시 정한다. 그 후 상부 화물 접근 관계와 야드 목적지 계획을 만든다. 접근 검사는 실제 두 컨테이너의 평면 외형이 겹치는지 확인한다.
   좌우 기준선은 실제 `ShipHull` 중심인 월드 X=-32m이며, 초기 격자 중심 -35.5m를 재사용하지 않는다. 테스트는 선체 컴포넌트에서 직접 읽은 중심으로 횡경사를 독립 재계산한다. 수직 모멘트의 Z=0은 같은 시뮬레이션 기준면을 사용한다.
8. 기존 전체 화물의 20/40/45ft 비율 28/70/2와 개별 ID·질량·예약 정보는 보존한다. `PortCallOrder`는 합성 항로 예약이며, 현재 시나리오는 환적/전량 하역으로 모든 목적항 화물을 내린다. 특정 기항항 화물만 선택 하역하는 항차 모델은 이번 변경에 포함하지 않는다.

## 웹과 기록

선박 상세의 적재 표는 이제 **실제 초기 Actor에 적용된 계획**이다. 컨테이너 상세에는 초기 Bay/Row/Tier, 20ft 자리, 아래 받침 ID, 초기 월드 좌표를 표시한다. 호환성을 위해 JSON 키 `ship_loading_preview`를 유지하되 `applied_to_arrival=true`, `state_basis=initial_arrival_not_live_hydrostatics`로 구분한다. GM·경사·고박은 **입항 초기 상태의 계산값**이며 하역 중 남은 화물과 밸러스트의 실시간 복원성 값이 아니다.

선박 전체 GM·경사는 초기 계획을 모두 구성한 뒤의 값이다. 배치 표의 `gm_after_m`/`heel_after_deg` 및 각 열의 스택·고박 값은 해당 화물을 계획에 추가한 직후의 구성 단계 값이다. 아래쪽 화물 행의 스택 값을 최종 전체 열 하중으로 읽으면 안 된다.

프로필 `ship_arrival_layout=applied_bay_row_tier`와 로그 `SHIP_ARRIVAL_STOWAGE`가 실제 적용 여부를 남긴다. `Stowage_Planning.json`의 가정과 물리 배치가 같은 갑판 높이를 사용한다. 의도적인 과부하 고장 주입은 정상 예약 질량으로 배치한 후, 기존처럼 STS의 실제 하중 검증에서 거절한다.

## 범위와 검증

600개 기본 예약에 적용된 초기 계획(각 200개, 갑판 상면 4.5m):

| 선박 | 사용한 최고 층 | 초기 보정 GM | 초기 횡경사 추정 | 종방향 CG 편차 |
|---|---:|---:|---:|---:|
| 1 | 2 | 3.1227m | 0.1059° | -0.0520m |
| 2 | 3 | 2.9900m | 0.1302° | -0.0620m |
| 3 | 2 | 3.1234m | 0.1284° | -0.0492m |

위 수치는 모의 경하중량·KM·질량으로 계산한 값이며 실제 선박 측정/승인 값이 아니다.

실제 승인 hydrostatic table, 밸러스트 탱크, 선체 전단력·굽힘 모멘트, 전체 항차 중 복원성, 해치 커버 접근, 셀 가이드/고박 장비의 선박별 제원은 아직 모델링하지 않았다. 현재의 일정 KM, 종방향 무게중심 한계와 정적 고박 근사로 이 항목들을 검증했다고 표시하지 않는다.
